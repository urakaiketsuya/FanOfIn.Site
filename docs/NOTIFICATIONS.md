# Notifications and deck legality

Use `useToast().notify({ message, tone, key, action })` for completed user actions and recoverable operation failures. Actions accept a callback (which may return a promise) or a router `to` destination. Keep messages brief and describe the actual result: a local draft is not an account save.

The provider in `main.tsx` owns one visible toast plus at most four waiting. A key replaces feedback from the same operation and component. Ordinary confirmations last six seconds; errors and actionable notifications persist. Timers pause on hover, focus, and hidden tabs. Dismiss is always available; async actions disable controls until completion and keep failures visible. Callback actions are removed when their owner unmounts, avoiding stale actions after navigation. New editor operations explicitly invalidate the previous edit's Undo.

`ToastViewport` reserves space in the sticky app header. `DialogSheet` registers an in-flow host within its modal chrome; only the latest mounted dialog host renders notifications. This keeps actions within modal focus isolation and avoids covering card controls or save footers. No animation is used. Do not add toast-only validation errors, fire notifications during ordinary hydration, or toast every quantity tap. Keep draft state, required fields, missing cards, sync conflicts, and legality warnings inline.

Initial integrations include Builder/My Decks actions, collection ownership (with transaction Undo), card assignments, decklist copy/export, favorites, official products, imports, comparison selection, account changes, and browser connectivity restoration. Offline status stays inline, and connectivity messages never claim a successful sync. Remaining feature-specific messages can migrate as those flows are revised; don't move persistent guidance into timers.

`shared/src/deckLegality.ts` derives structured card issues from the selected format and current catalog. Only an explicit zero limit is called banned. Unknown formats, unresolved cards, and missing format records remain unverified. Active deck checks include main, material, and sideboard; maybeboard does not invalidate the active deck. Adding/increasing banned cards triggers one warning with Undo, while hydration only renders persistent feedback. Historical lists explicitly label warnings as current-catalog rules. These checks do not establish legality at the date of an old event.
